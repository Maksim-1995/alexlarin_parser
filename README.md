# Парсер тренировочных вариантов alexlarin.net

Скрипт собирает условия и ответы тренировочного варианта по профильной математике,
распознаёт формулы через Gemini и формирует Excel с отдельными рисунками.

Проверенный источник: [тренировочный вариант № 542](https://alexlarin.net/ege/2026/trvar542.html).

## Результат

После запуска создаются:

- `output/trvar542/tasks.xlsx` — таблица с листами `Tasks` и `about`;
- `output/trvar542/images/` — четыре рисунка к заданиям 1, 3, 8 и 11;
- `trvar542_result.zip` в корне проекта — тот же Excel и папка с рисунками.

В ZIP находятся пять файлов: `tasks.xlsx`, `images/image_82.jpeg`,
`images/image_83.jpeg`, `images/image_198.png` и `images/image_200.png`.
Эти имена и количество рисунков относятся к варианту № 542.

Лист `Tasks` содержит колонки:

| Колонка | Содержание |
| --- | --- |
| `task_num` | Номер задания от 1 до 19 |
| `condition` | Условие с формулами в читаемой текстовой записи |
| `image_name` | Имя отдельного рисунка; пусто, если рисунка нет |
| `solution` | Пусто: решения не требуются на этом этапе |
| `answer` | Ответ, сохранённый текстом |

Лист `about` содержит класс, год экзамена, дату формирования выгрузки,
название варианта, ссылки на источники и способы получения условий и ответов.
Дата выгрузки не выдаётся за дату публикации варианта.

## Установка

Проект проверен на Python 3.12. Нужен сетевой доступ к alexlarin.net и Gemini API.

Клонируйте репозиторий или скачайте исходники. Из корня проекта выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Перед первым распознаванием задайте ключ Gemini в переменной окружения.
В Bash ключ можно ввести без отображения в терминале:

```bash
read -rsp "Ключ Gemini API: " GEMINI_API_KEY
export GEMINI_API_KEY
```

## Запуск

Вариант по умолчанию:

```bash
python -u main.py
```

Явное указание ссылки:

```bash
python -u main.py --url "https://alexlarin.net/ege/2026/trvar542.html"
```

Только распознавание уже скачанного PDF, без повторного скачивания с сайта:

```bash
python -u recognizer.py --pdf input/trvar542.pdf
```

Дополнительная утилита `refine_conditions.py` позволяет повторно распознать
отдельные задания, если при сверке обнаружена неточность. Например:

```bash
python -u refine_conditions.py 6 13 18
```

Она сохраняет прежний кэш, обновляет только выбранные условия и не запускается
автоматически из `main.py`. После такой проверки Excel пересоздаётся обычным
запуском `main.py`.

При отсутствии подходящего кэша OCR выполняет до 19 последовательных запросов:
по одному на каждое задание. Результат сохраняется после каждого успешного ответа.
После сбоя ту же команду можно запустить повторно: уже сохранённые условия
для той же конфигурации не отправляются модели заново.

Кэш учитывает содержимое PDF, модель, инструкцию, разрешение и версию обработки.
При изменении этих параметров требуется новое распознавание; прежний кэш
сохраняется в резервной копии. При готовом кэше запросов OCR нет,
но `main.py` по-прежнему загружает исходники с сайта.

## Как обрабатываются данные

1. `downloader.py` загружает HTML, PDF и файлы ответов.
2. PyMuPDF читает текстовый слой для поиска номеров, координат и метаданных.
   Регулярное выражение в `parsers.py` выделяет задания по обозначениям `1.`, `2.`
   и так далее.
3. `recognizer.py` готовит крупные изображения областей заданий при 300 dpi.
   Gemini (`gemini-3.5-flash-lite`) переписывает условия и формулы в JSON с LaTeX.
   В итоговую таблицу попадают условия из OCR, а не повреждённые формулы
   из текстового слоя PDF.
4. `math_text.py` преобразует поддерживаемую математическую запись для Excel:
   например, `\vec{a}` становится `a⃗`, `\sqrt{43}` — `√43`, а `x^2` — `x²`.
5. Ответы 1–12 извлекаются регулярным выражением из распакованного JavaScript.
6. Ответы 13–19 перенесены вручную с опубликованной картинки
   [trvar542.png](https://alexlarin.net/ege/2026/trvar542.png)
   и хранятся в `input/trvar542_answers.json`. Источник и ручной способ переноса
   указаны в метаданных. Эти ответы не выдаются за автоматическое распознавание.
7. Встроенные рисунки извлекаются через `page.get_images()` и связываются
   с заданиями по положению в той же колонке. Для варианта № 542 служебные
   изображения не имеют подходящего задания и не попадают в результат.
8. `exporter.py` записывает Excel и упаковывает результат в ZIP.

## Исходники и промежуточные файлы

В `input/` сохраняются скачанные HTML, PDF, JavaScript, опубликованная таблица
ответов, текстовый слой, кэш условий и исходные ответы API.
Изображения для OCR находятся в `input/trvar542_ocr/`.
Они нужны для распознавания и не включаются в итоговый ZIP.

Перед новой выгрузкой прежняя папка результата переносится
в `input/previous_output/`. В `output/<variant_id>/` создаются только новый
`tasks.xlsx` и `images/`.

В Git включены исходный код, тесты и небольшой JSON с вручную перенесёнными
ответами. Скачанные файлы, кэш, резервные копии и результаты исключены.

## Проверки

```bash
python -m pytest -q
```

Тесты проверяют парсинг, валидацию ответов, продолжение OCR после сбоя,
использование и обновление кэша, а также преобразование вложенных дробей,
корней, степеней, векторов и систем. Ответы API в тестах подменяются,
поэтому для тестирования не нужен ключ и не расходуется API-квота.

Успешные тесты и наличие 19 строк не доказывают математическую точность OCR.
Условия варианта № 542 дополнительно сверены с исходным PDF.

## Формулы и границы применимости

В Excel используется линейная математическая запись Unicode. Например,
`x^(log₃ x)` обозначает степень, а `log[|x|](...)` — логарифм с основанием `|x|`.
Дробные черты записаны через `/` с явными скобками. Системы разбиты на строки.
Это текст в ячейке, а не точная типографская копия формулы из PDF.
Исходная запись LaTeX сохраняется в OCR-кэше.

Поиск областей рассчитан на две колонки, 19 заданий и номера в текстовом слое.
Для сканированного PDF без текстового слоя или другой вёрстки потребуется
доработать поиск областей. Преобразователь формул поддерживает используемые
команды и сообщает об неизвестных, не удаляя их молча.

Для другого варианта параметра `--url` недостаточно: нужно подготовить
`input/<имя_pdf>_answers.json` с ответами 13–19 и соответствующей ссылкой
на опубликованную таблицу, затем проверить вёрстку, рисунки и результаты OCR.
Ответы в этом JSON должны быть строками; поля файла — `source_url`, `method`
и `answers`, где ключи ответов — строки от `"13"` до `"19"`.
