# Парсер тренировочных вариантов alexlarin.net

Парсер получает условия из изображений PDF, извлекает опубликованные ответы,
классифицирует задачи и формирует Excel с рисунками и отдельный ZIP.
В проекте используются интеграции провайдеров **Gemini, NVIDIA и DeepSeek**.
Их текущие роли различаются:

| Провайдер | Где используется | Ключ окружения |
|---|---|---|
| DeepSeek | Основной пакетный конвейер OCR и классификации | `DEEPSEEK_API_KEY` |
| Gemini | Прежние OCR, уточнение условий и legacy-классификация; локальная совместимость кэшей 542 | `GEMINI_API_KEY` |
| NVIDIA | Отдельная проверочная интеграция `check_deepseek.py --provider nvidia` | `NVIDIA_API_KEY` |

В основном CLI пока нет общего переключателя трёх провайдеров или автоматического
перехода между ними. Наличие ключа Gemini/NVIDIA в окружении не меняет провайдера
основного конвейера. Указанная роль NVIDIA не означает готовую обработку PDF
через этот профиль.

Созданы пилотные выгрузки основных вариантов №1–12. Последний пакет №6–12
содержит замечания к OCR и классификации и остаётся `NEEDS_REVIEW`.
Код выбора работает по реальным ссылкам архива №1–551; массовый запуск
не выполнялся. Вариант 4* имеет отдельную идентичность и не заменяет основной №4.

## Установка и конфигурация

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

Последнюю команду выполняйте только если `.env` ещё отсутствует. Существующий
`.env` сохраняется; переменные окружения имеют приоритет над значениями файла.
Клиент читает простые строки `KEY=value`, не исполняет shell и не раскрывает
значения `$VARIABLE` или `$(command)`.

```dotenv
# Ключи провайдеров. Секреты задаются локально; этот шаблон значений не содержит.
# Основной пакетный CLI: DeepSeek.
DEEPSEEK_API_KEY=

# Gemini: прежние OCR/уточнение условий и legacy-классификация.
GEMINI_API_KEY=

# NVIDIA: отдельный профиль в check_deepseek.py --provider nvidia.
NVIDIA_API_KEY=

# Настройки основного DeepSeek-клиента.
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_CONNECT_TIMEOUT=15
DEEPSEEK_READ_TIMEOUT=120
DEEPSEEK_MAX_TOKENS=16384
DEEPSEEK_CLASSIFICATION_THINKING=disabled

# Разрешение изображений страниц основного OCR.
OCR_DPI=300
```

Секрет заполняется только локально. Ранее использовавшийся
`DEEPSEEK_REQUEST_TIMEOUT` принимается как запасное имя тайм-аута чтения.
Один `DeepSeekClient` обслуживает OCR и классификацию всего последовательного
пакета. OCR всегда отправляет `thinking: {type: disabled}`; классификация имеет
отдельную настройку `disabled`/`enabled`. Начальное значение — `disabled`.
Клиент использует уже установленный `requests`, отдельный SDK не требуется.

Gemini использует установленный `google-genai`. Параметры его прежних инструментов
и NVIDIA-профиля задаются в соответствующих модулях; переменные `GEMINI_MODEL`,
`NVIDIA_MODEL` или `AI_PROVIDER` текущим кодом не читаются и в шаблон не добавлены.
Основной CLI загружает `.env` сам. Отдельные `check_deepseek.py`, `recognizer.py`
и `refine_conditions.py` читают ключи из окружения процесса; файл `.env` эти
утилиты самостоятельно не загружают. Заполнение шаблона не запускает запросы.

Формат проверен по официальным руководствам DeepSeek:
[Vision](https://api-docs.deepseek.com/guides/vision/),
[JSON Output](https://api-docs.deepseek.com/guides/json_mode/),
[Thinking](https://api-docs.deepseek.com/guides/thinking_mode/).
Изображения передаются в `user.content` через `image_url` с base64;
ответ — JSON object. Непустой content, HTTP 2xx и `finish_reason=stop` обязательны,
но сами по себе не подтверждают точность распознавания.

## Команды

План выбора №1–5: загрузка/чтение каталога разрешена, модель не вызывается:

```bash
python -u main.py --batch 1-5 --plan
```

Реальный пилот только №1–5:

```bash
python -u main.py --batch 1-5
```

Первый вариант можно проверить отдельно, затем запустить весь пилот: готовые
страницы и классификация первого варианта будут прочитаны из кэша.

```bash
python -u main.py --url https://alexlarin.net/ege/2013/trvar1.html
python -u main.py --batch 1-5
```

Возобновление конкретной попытки по пути из вывода команды:

```bash
python -u main.py --resume reports/RUN_ID/manifest.json
```

Манифест определяет точные URL и каталоги кэшей каждого варианта. Возобновляются
также изолированные кэши прерванного `--fresh-ai`. Новая попытка получает новый
отчёт, ссылающийся на предыдущий; готовые страницы не оплачиваются повторно.

Повторный запуск с проверенными локальными исходниками:

```bash
python -u main.py --batch 1-5 --local-only
```

Свежий AI-прогон для измерений, сохраняющий обычные кэши и исходники:

```bash
python -u main.py --batch 1-5 --fresh-ai --local-only
```

Его кэши остаются в `cache/fresh/<run_id>/` и могут быть возобновлены.
`--fresh-ai` и `--resume` имеют разные назначения и вместе не применяются.

Пилот №6–12 содержит семь вариантов, поэтому лимит пакета задан явно.
Финальные классификации этого пилота используют отключённый thinking:

```bash
DEEPSEEK_CLASSIFICATION_THINKING=disabled python -u main.py --batch 6-12 --max-variants 7 --local-only
```

`--local-only` требует заранее сохранённых и проверенных исходников. Для
проверки полного повторного запуска без возможности отправить новый запрос:

```bash
DEEPSEEK_API_KEY='' DEEPSEEK_CLASSIFICATION_THINKING=disabled python -u main.py --batch 6-12 --max-variants 7 --local-only
```

Пустой ключ имеет приоритет над `.env`. Готовые совместимые кэши читаются без
ключа; при отсутствии кэша запуск сообщит об ошибке до отправки запроса.

Без `--local-only` недостающие источники загружаются. Нет предварительных
пингов модели. Размер пакета по умолчанию ограничен пятью вариантами
(`--max-variants 5`). План может содержать больший диапазон. Расширение диапазона
использует тот же код, но требует отдельного решения о бюджете и проверке качества.

Сохранена команда одиночного варианта, включая прежний вариант по умолчанию:

```bash
python -u main.py --url https://alexlarin.net/ege/2026/trvar542.html
python -u main.py
```

Коды завершения: `0` — SUCCESS, `2` — NEEDS_REVIEW, `1` — FAILED,
`130` — прерывание пользователем. NEEDS_REVIEW означает, что результат создан,
но есть пропуски ответов или замечания к содержанию/рисункам/оформлению.

## Поток и ответственность модулей

Реализация находится в пакете `alexlarin_parser`. Один конвейер обслуживает
все варианты; их исходники, кэши и результаты по-прежнему изолированы.

```text
alexlarin_parser/
  __main__.py, cli.py       # запуск, аргументы, коды завершения
  context.py, paths.py      # идентичность варианта и корень проекта
  pipeline.py               # этапы, возобновление, состояния и отчёты
  provider.py               # прямой DeepSeek без автоматических повторов
  io.py, requests_counter.py
  sources/
    catalogue.py            # реальные href архива и выбор вариантов
    parsing.py              # HTML/JS/PDF, метки и расположение задач
    service.py              # проверенные источники, манифесты, Range
    downloader.py           # HTTP и проверка файлов
  ocr/
    rendering.py            # изображения страниц и колонок
    recognition.py          # OCR, постраничные кэши и сборка фрагментов
  classification/
    catalogues.py           # деревья CSV, листья, проверка категорий
    service.py              # основной DeepSeek-протокол варианта
    legacy.py               # прежний Gemini-протокол 1–19
  exporting/
    images.py               # рисунки, матрицы размещения и маски
    workbook.py, metadata.py # Tasks и about
    archive.py              # ZIP по явному списку файлов
    service.py              # оформление, проверка, публикация с откатом
  formatting/
    latex.py, math_text.py, html.py
  prompts/
    ocr.txt, classification.txt
    classification_numeric_legacy.txt
    classification_gemini_legacy.txt
```

Основной поток: `sources.service` → `ocr.recognition` →
`classification.service` → `exporting.service`. Им управляет `pipeline.py`.
Функции чистого разбора, справочники, рендер и операции записи выделены отдельно,
чтобы менять и тестировать этапы независимо.

Основные промпты находятся в UTF-8 ресурсах `prompts/`. Два дополнительных
файла сохраняют исторические протоколы совместимости. Загрузчик не удаляет
пробелы и переводы строк: точный текст входит в identity AI-кэшей. Сам перенос
промптов не изменил их тексты, версии, схемы или fingerprints кэшей.

Корневые `main.py`, `pipeline.py`, `classification.py`, `variant_sources.py`,
`variant_ocr.py`, `variant_export.py`, `provider.py`, `exporter.py` и остальные
перенесённые модули оставлены совместимыми точками импорта. Старый запуск
`python main.py ...` сохранён. Новый способ запуска:

```bash
.venv/bin/python -m alexlarin_parser --help
.venv/bin/python -m alexlarin_parser --batch 6-12 --plan --local-only
```

Новый код импортирует реализации из пакета. Подмены зависимостей в тестах
направляются в модуль-владелец функции, например `classification.service`
или `exporting.service`, а не в фасад с реэкспортами.

`legacy_sources.py`, `recognizer.py`, `parsers.py` и прежние утилиты сохранены
для совместимости и локальных регрессий. Ограничения 19 задач, 12 JS-ответов и
ручного переноса ответов 13–19 не относятся к другим вариантам. Основной поток
не вызывает старый Gemini API; чтение проверенного OCR-кэша 542 остаётся локальным.

Содержательная сверка учитывает хеши **реальных модулей** `exporting/` и
`formatting/`. После переноса её прежние fingerprints становятся несовместимыми;
старые findings/approved не переносятся автоматически. AI-кэши остаются совместимыми,
а прежние файлы сверки и готовые архивы сохраняются без изменений.

Условия берутся с изображений. Текстовый слой PDF определяет исходные метки и
расположение задач и помогает проверить полноту; он не подменяет видимые формулы.
Две колонки передаются в одном запросе только при обнаружении двух групп начал
задач на странице. В остальных случаях отправляется целая страница.

## Контекст и расположение файлов

Устойчивый ключ включает год и исходный код, например `ege_2013_trvar1`.
Суффиксы и дополнительные версии получают другие ключи. `task_num` уникален
только внутри варианта: внутренняя связь включает `variant_key` и `source_label`.

```text
input/catalogue/                         # общий HTML архива и разобранный каталог
input/variants/<variant_key>/source/      # HTML, PDF, JS, опубликованные ответы
  source_manifest.json                   # точные URL, SHA-256, происхождение файлов
input/variants/<variant_key>/cache/
  ocr/page_001.json                       # только проверенная готовая страница
  conditions.json                        # собранные условия, не подменяет page caches
  classification.json
  fresh/<run_id>/                        # изолированная измерительная попытка
input/variants/<variant_key>/debug/
  source_inspection.json
  runs/<run_id>/                         # ответы API, попытки, проверки экспорта
output/<variant_key>/                    # только tasks.xlsx и рисунки этого варианта
archives/<variant_key>_result.zip
archives/trvar542_result.zip             # прежний проверенный архив 542
reports/<run_id>/manifest.json
reports/<run_id>/<variant_key>.json
data/exams.csv
data/topics.csv
preview.html                             # инструмент отдельно от выдачи
```

Загрузка проверяет статус, непустоту и фактический тип содержимого. HTML ошибки
нельзя сохранить как PDF. Бинарный локальный файл принимается при совпадении
URL и хеша в source manifest. HTML/PDF дополнительно проверяются по номеру,
году и реальным ссылкам. Новые файлы записываются через временный файл;
неудачная загрузка не заменяет исправный источник. При зависании передачи
бинарных исходников предусмотрена сборка из HTTP Range по 8192 байта: проверяются
Content-Range, длина, общий размер и ETag; каждая сетевая попытка считается отдельно.

Для точного URL `https://alexlarin.net/ege/2026/trvar542.html` разрешена безопасная
копия проверенных плоских исходников `input/trvar542.*` в новый каталог. Прежние
источники и `output/trvar542/` сохраняются. Проверенный архив перенесён из корня
в `archives/trvar542_result.zip`; его имя и содержимое не изменены. Хеш и состав
проверены, запись о переносе находится в `reports/maintenance/archive_542_move.json`.
Ни один файл 542 не подставляется другому варианту. Новая выдача 542 имеет ключ
`ege_2026_trvar542` и путь `archives/ege_2026_trvar542_result.zip`: это отдельная
выгрузка общего CLI, которая не перезаписывает прежний проверенный архив.

## Старые B/C и опубликованные ответы

Для №1 фактические задачи — B1–B14,C1–C6: **20 задач**, несмотря на число 18
во вступлении. В Excel это `task_num=1..20`. В кэшах и отчётах остаются
`source_label`, оригинальная метка, `section`, `page_numbers` и фрагменты.
Метки B1 и C1 имеют разные условия и ответы. Явная нормализация допускает
визуальные пары B/В и C/С; другие буквы не исправляются догадками.

Ответы первой части берутся из HTML-таблиц. Для современных страниц сохранён
разбор JS. Картинка опубликованных ответов второй части прикладывается к
последнему OCR-запросу, возвращается отдельным полем `answers` и не считается
условиями. Это переписывание готовых ответов: решать задачи и придумывать
недостающие ответы запрещено. Ручной перенос 13–19 от 542 применяется только
к его точному URL картинки. Недоступный источник или нечитаемый ответ означает
явный пропуск и NEEDS_REVIEW; дополнительного скрытого запроса нет.

Ответы — строки, включая десятичные запятые. Формулы, дроби, интервалы,
иррациональные ответы и геометрические обозначения оформляются в LaTeX.
Одна строка Tasks — одна основная задача, все её подпункты остаются внутри
condition. Перед А), Б), В) вне формул добавляется `<br>`. Переносы `\\` внутри
`cases` и других LaTeX-систем сохраняются.

## Справочники и правила классификации

CSV проверяются целиком: колонки, дубли, ID, родители, отсутствующие связи,
циклы. ID сравниваются после точной нормализации, а не поиском подстроки.

- `exams_id`: ровно один существующий числовой ID конечного потомка корня 2
  («математика профиль»), на любой глубине. У листа нет детей по полному CSV.
- `topics_id`: ровно один числовой ID конечного потомка корня 1 («Математика»)
  либо осмысленное новое название строкой, когда подходящего листа нет.
  Выдумывать числовой ID, выбирать родителя или подгонять справочник нельзя.

В модель отправляются условия всех задач **одного** варианта и только
допустимые категории с полными путями. Модель выбирает раздельные метки E/T;
они однозначно преобразуются в числовые exams_id/topics_id и проверяются
по независимым деревьям. Это предотвращает перенос числового ID exams в topics. Номер старой задачи не сопоставляется
с номером современной задачи ЕГЭ. Проверка результата требует все task_num
ровно по одному разу; справочники exams/topics проверяются независимо.
Структурная проверка не доказывает, что новая тема действительно необходима:
семантическое соответствие относится к содержательной сверке.

## Кэши, бюджет, ошибки и отчёты

На холодном успешном запуске P страниц требуют **P OCR + 1 классификацию**.
Страница только с инструкциями также получает один OCR-запрос и может вернуть
пустой список. Картинка ответов не создаёт отдельного запроса. Если последняя страница
содержит только часть задач (например C6 в №5), область answers явно включает
все метки картинки, независимо от меток tasks этой страницы.
Полный повтор без изменений: **0 OCR + 0 классификаций**.

Постраничный кэш связан с variant_key/URL, SHA-256 PDF, номером страницы,
схемой рендера/кадрирования, провайдером, моделью, существенными параметрами,
версией/хешем промпта, схемой ответа и хешами приложенных картинок ответов.
Продолжения собираются по исходной метке в порядке страниц; отличающийся
фрагмент не удаляется как дубликат.

Кэш классификации дополнительно учитывает условия, метки, оба справочника,
допустимые множества ID и правила классификации. Изменение CSV повторяет только
классификацию. Изменение одного варианта не отменяет кэши других вариантов.
Ошибочный, пустой, оборванный (`finish_reason=length`) или структурно неполный
ответ не сохраняется как готовая страница/классификация. Завершённые страницы
и прежняя выдача сохраняются.

Полный старый Gemini OCR-кэш 542 может быть прочитан **без обращения к Gemini**
только для точного URL/ключа 542, совпадающего PDF SHA-256, полной нумерации 1–19
и одной из точных поддержанных legacy identity (модель, prompt, schema, render).
Его провайдер остаётся Gemini; он не превращается в DeepSeek-кэш. Старые
классификационные файлы Gemini автоматически не принимаются новой классификацией.
Успешные числовые кэши прямого DeepSeek v1 читаются только при точной identity
поддержанного промпта v2, неизменных условиях/CSV/провайдере и повторной проверке
всех конечных ID; их исходный протокол и ответ сохраняются.
Старые функции `recognizer.py`/`classify_tasks` оставлены для локальных регрессий;
основной CLI их модельные вызовы не использует.

HTTP-повторы AI и переходы по редиректам отключены. Каждая фактическая попытка,
включая timeout или HTTP-ошибку, учитывается непосредственно перед отправкой.
Ошибки ключа/доступа/баланса (401/402/403) прекращают новые модельные вызовы пакета.
Ошибка отдельного источника/варианта фиксируется отдельно. Сетевые загрузки
источников учитываются отдельно от модельных запросов. Неизвестный usage
отмечается явно; стоимость без известного тарифа и полного usage не вычисляется.

Манифест содержит URL, ключ, этап, SUCCESS/NEEDS_REVIEW/FAILED, число страниц,
задач/рисунков/ответов, пропуски, замечания, ошибки, пути, число попыток, время
этапов и usage. `previous_result` и `result_current_attempt` различают прежние
артефакты и выдачу текущей попытки. Ответы API и диагностические данные остаются
в debug, без заголовков Authorization и без секретов.

Содержательная сверка формул, опубликованных ответов, рисунков и тем требуется
после структурных проверок. Пока её нет, статус NEEDS_REVIEW. Поле
`review_fingerprint` в verification связывает проверку с конкретными данными;
совпадающий `debug/content_review.json` с `approved: true` и `fingerprint`
подтверждает выполненную сверку. Другие предупреждения и пропуски остаются
причиной NEEDS_REVIEW. Этот файл нельзя создавать только ради смены статуса.

## Формат выдачи и preview

`Tasks` содержит ровно семь колонок в порядке:

```text
task_num, condition, image_name, solution, answer, exams_id, topics_id
```

`solution` пустой. Несколько частей рисунка разделяются настоящим переводом
строки в `image_name`. Рисунки относятся только к задачам текущего варианта;
скриншоты всех задач, эмблемы и инструкции в выдачу не включаются. Встроенные
рисунки извлекаются отдельно; границы векторных рисунков требуют визуальной
проверки и получают предупреждения. Скан всей страницы не выдаётся за рисунок.

Лист `about` содержит заголовки и одну строку значений, ровно 11 полей:

```text
class, year, date, topic, exam_id, title, code, source_name, is_public, source_url, description
```

Неизвестные поля пустые; отсутствующая дата публикации не выдумывается.
`about.exam_id` относится к экзамену целиком, `Tasks.exams_id` — к задаче.
Технические поля и source_label остаются в отчётах, а `variant_name` и
`answers_13_19_method` не возвращаются в Excel.

ZIP формируется по явному списку: `tasks.xlsx` + только итоговые рисунки этого
варианта, на одном уровне. Число записей = 1 + число рисунков; проверяются
image_name, наличие файлов, точный состав и целостность ZIP. JSON, HTML, PDF,
логи и preview в ZIP не попадают. Новая выдача и ZIP сначала проверяются во
временном каталоге. Замена использует резервную копию в debug/previous_results
с откатом при ошибке публикации.

`preview.html` находится в корне, поддерживает семь колонок, MathJax, `<br>`,
таблицы условий и несколько имён в image_name. Он показывает заголовок, год
и URL из about. Откройте файл в браузере, вставьте скопированные семь колонок
листа Tasks и обе строки about в соответствующие поля. Рисунки проверяются
по указанным именам в папке output; сам preview не читает файлы XLSX/картинок.
Для загрузки MathJax с CDN нужен доступ в интернет.
