# Инструкции для работы с alexlarin_parser

Этот документ описывает правила разработки, проверки и обработки данных в
репозитории `alexlarin_parser`. Применяй его ко всему проекту с учётом текущего
запроса пользователя. Явные инструкции пользователя имеют приоритет над
рекомендациями этого файла; уже согласованный объём работы не требует повторного
согласования обычных обратимых действий.

## 1. Язык и порядок работы

- Отвечай пользователю на русском, если он не попросил другой язык.
- Объясняй решения как Python-разработчику среднего уровня. Для HTML, алгоритмов
  и инфраструктуры добавляй необходимый практический контекст.
- Сначала изучи проект, затем вноси изменения. Начинай с `git status --short`,
  `README.md`, зависимостей, затронутых модулей и соответствующих тестов.
- Для поиска используй `rg` и `rg --files`. Не обходи без необходимости `.venv`,
  крупные исходники, кэши и бинарные артефакты.
- Сохраняй незакоммиченные изменения пользователя. Не выполняй `git reset`,
  `git clean`, удаление исходников или массовую перезапись выдач ради чистоты дерева.
- Доводи согласованную задачу до результата. Не останавливайся ради подтверждения
  обычных правок, чтения файлов или локальных проверок без платного API.
- Не расширяй диапазон платной обработки по собственной инициативе. Разрешённый
  пользователем диапазон сохраняет силу при продолжении той же задачи.
- Сообщай о существенных находках и проверках. В конце укажи результат, реальные
  пути, выполненные проверки и оставшиеся ограничения.

## 2. Назначение и архитектура

Проект получает тренировочные варианты с `alexlarin.net`, переписывает условия
с изображений PDF, извлекает опубликованные ответы, классифицирует задачи
и создаёт Excel с отдельными рисунками и ZIP для каждого варианта.

Это Python CLI. Не добавляй Django, веб-сервис, очередь задач или новый SDK,
если текущая задача этого не требует. Сохраняй рабочие зависимости и публичные
импорты. Разделяй обязанности существующих модулей:

| Модуль | Ответственность |
|---|---|
| `main.py` | CLI, выбор режима, коды завершения, совместимые прежние импорты |
| `pipeline.py` | Последовательные этапы, состояния вариантов, отчёты, применение сверки |
| `variant_sources.py` | Каталог реальных ссылок, `VariantContext`, проверка и разбор источников |
| `downloader.py` | HTTP-загрузка и проверка файлов |
| `variant_ocr.py` | Рендер PDF, постраничный OCR, кэши, сборка продолжений |
| `classification.py` | Деревья CSV, допустимые листья, классификация и проверка результата |
| `provider.py` | Настройки и единый прямой DeepSeek-клиент, журнал HTTP-попыток |
| `ai_requests.py` | Счётчики фактических модельных попыток |
| `pipeline_io.py` | Атомарная запись, JSON, SHA-256 и стабильные fingerprints |
| `variant_export.py` | Рисунки, подготовка выдачи, проверка Excel/ZIP, публикация с откатом |
| `exporter.py` | Запись Excel и ZIP по согласованному контракту |
| `export_metadata.py` | Поля и подготовка листа `about` |
| `latex_format.py`, `math_text.py`, `task_html.py` | Формулы, текст и подпункты |
| `parsers.py` | Существующие механизмы разбора задач и JS-ответов |
| `legacy_sources.py` | Ограниченная совместимость прежнего формата 542 |
| `recognizer.py`, `refine_conditions.py` | Прежние инструменты; не являются новым основным потоком |
| `preview.html` | Локальная проверка отображения Excel через TSV и MathJax |

Общий поток одного варианта:

1. Проверить справочники, идентичность и источники.
2. Прочитать совместимые постраничные кэши; распознать только недостающие страницы.
3. Собрать фрагменты задач и сопоставить опубликованные ответы по исходным меткам.
4. Классифицировать все задачи одного варианта одним запросом либо прочитать кэш.
5. Подготовить и проверить Excel, рисунки и ZIP во временном каталоге.
6. Опубликовать выдачу с резервной копией и возможностью отката.
7. Применить относящуюся к этим данным содержательную сверку и сохранить отчёт.

Код обработки общий. Отдельные `.py` для каждого варианта или задания не нужны.
Изоляция достигается контекстом и каталогами данных.

## 3. Идентичность и расположение файлов

Различай **вариант экзамена** и **задачу внутри варианта**. Если запрос говорит
«варианты №6–12», это семь полных вариантов со всеми их задачами.

- `variant_key` включает год и исходный код, например `ege_2013_trvar6`.
- Номер, код, год, `source_url`, обнаруженные URL и пути принадлежат контексту.
- Дополнительные версии и суффиксы имеют собственную идентичность. Основной №4
  нельзя заменить вариантом 4*.
- `task_num` уникален только внутри варианта. Для объединений используй
  `variant_key` и `source_label`; B1 и C1 — разные задачи.
- Во внутренних данных сохраняй `source_label`, `original_label`, `section`,
  `page_numbers` и фрагменты. В итоговый Excel технические поля не добавляются.

```text
input/catalogue/                         # сохранённый каталог реальных ссылок
input/variants/<variant_key>/source/      # HTML, PDF, JS, картинки опубликованных ответов
  source_manifest.json                   # точные URL, SHA-256, происхождение файлов
input/variants/<variant_key>/cache/
  ocr/page_001.json                       # проверенная готовая страница
  conditions.json                        # собранные задачи и ответы
  classification.json
  fresh/<run_id>/                        # отдельная попытка --fresh-ai
input/variants/<variant_key>/debug/
  source_inspection.json
  content_review.json                    # сверка с fingerprint конкретных данных
  runs/<run_id>/                         # API-ответы, попытки, verification, резервные копии
output/<variant_key>/                    # tasks.xlsx и только рисунки этого варианта
archives/<variant_key>_result.zip
reports/<run_id>/manifest.json
reports/<run_id>/<variant_key>.json
data/exams.csv
data/topics.csv
preview.html
```

Все задания одного варианта находятся в одном `tasks.xlsx`, по одной строке
на основную задачу. Для каждого варианта создаётся отдельный ZIP.
`input`, `output`, `archives`, `reports`, `.env` и `.venv` содержат локальные
артефакты либо окружение и в значительной части исключены через `.gitignore`.
Не считай отсутствие этих файлов в чистом клоне ошибкой кода.

## 4. Источники: только проверенное соответствие

- Выбирай варианты из реальных `href` архива `https://alexlarin.net/trvar.html`.
  Не строй адреса всего архива по шаблону одного года.
- Используй существующий проверенный локальный источник перед новой загрузкой.
  Совпадение имени файла само по себе недостаточно: проверяй URL и SHA-256.
- Проверяй HTTP-статус, непустоту, фактический тип, номер и год. HTML ошибки
  нельзя сохранять как PDF. При неудаче не заменяй прежний исправный файл.
- Сохраняй источники атомарно. Для HTTP Range проверяй Content-Range, длину,
  общий размер и ETag; учитывай каждую сетевую попытку отдельно от AI.
- Метаданные получай из реального источника. Не придумывай дату публикации,
  класс, год или дополнительные атрибуты ради заполненности Excel.
- Количество задач определяй по фактическим меткам, а не только по вступлению.
  В старых PDF инструкция про 18 задач может соседствовать с 20 задачами.
- Нормализуй только явно принятые визуальные пары B/В и C/С. Не объединяй B1/C1.
- Учитывай Unicode-разделители диапазона года: «2012‐2013» означает 2013 год.
  Поддержка разделителя не должна разрешать действительно неверный год.
- Не принимай фразу «В 2008 году» за B2008 и геометрическую вершину B1 внутри
  условия за новое начало задачи. Проверяй расположение метки и страницы задачи.

## 5. OCR и опубликованные ответы

- Основной источник формул — изображение страницы PDF. Текстовый слой помогает
  определить метки и расположение, но не заменяет видимые корни, степени и дроби.
- Выполняй один OCR-запрос на страницу: полная страница либо её реальные колонки
  в одном запросе. Не разрезай любой PDF пополам без проверки макета.
- OCR переписывает условия **без решения**. Не дополняй формулы по ожидаемому
  ответу, не исправляй источник догадками и не генерируй отсутствующие ответы.
- Продолжение на другой странице или в следующей колонке относится к той же
  `source_label`. Сохраняй порядок и отличающиеся фрагменты; подпункты не становятся
  отдельными задачами. Страница инструкций может вернуть пустой список задач.
- Проверяй оболочку API, JSON, схему, ожидаемые метки и продолжения. Сохраняй
  страницу как готовую только после структурной проверки. `finish_reason=length`
  означает незавершённый результат; `stop` не доказывает точность содержания.
- Ответы первой части извлекай из реальных HTML-таблиц или JS соответствующего
  варианта. HTML/JS имеют приоритет при конфликте с OCR; конфликт отражай в отчёте.
- Опубликованную PNG с ответами второй части прикладывай к последнему запросу
  страницы, возвращай её отдельно в `answers`. Область ответов включает все
  опубликованные метки, даже если на последней странице только одна задача.
- Пустой или нечитаемый опубликованный ответ оставляй отсутствующим с причиной
  и статусом `NEEDS_REVIEW`. Не восстанавливай даже привычный математический
  символ, если в источнике виден только утраченный глиф.
- Храни ответы строками, включая десятичные запятые и математическую разметку.
  Сверка переноса опубликованного ответа не означает решение самой задачи.
- Ручное исправление по источнику должно иметь явное происхождение и сохранять
  исходный ответ модели. Не подделывай провайдера и не редактируй кэш ради видимости
  успешного AI-ответа.

## 6. Классификация

Сначала прочитай и проверь полные `data/exams.csv` и `data/topics.csv`: колонки,
нормализованные ID, дубли, родителей, отсутствующие связи и циклы.

- `exams_id`: ровно один существующий числовой ID конечного потомка корня 2
  («математика профиль»), на любой глубине. Фильтр только `parent_of_exam == 2`
  неверен.
- `topics_id`: ровно один числовой ID конечного потомка корня 1 («Математика»).
  Если подходящего листа нет, допускается осмысленное новое название строкой.
- Лист — запись, чей ID не является родителем другой записи в полном справочнике.
  Проверяй точное совпадение нормализованных ID, не подстроку.
- Не выдумывай числовые ID, не выбирай родителей и не меняй CSV под ответ модели.
- Передавай модели все задачи только одного варианта и допустимые категории
  с полными путями. В основном протоколе пространства выбора E/T разделены;
  их преобразование в числовые ID выполняется и проверяется независимо.
- Результат должен содержать все `task_num` ровно по одному разу. Массивы ID
  или несколько категорий в одной ячейке не соответствуют контракту.
- Определяй тему по условию, не по номеру старой или современной задачи ЕГЭ.
- Структурно допустимый ID может быть семантически неверным. Алгебраическая
  система с параметром не становится тригонометрической из-за номера C5;
  арифметическое действие внутри чтения графика не определяет тему всей задачи.
- Для новой строковой темы также проверяй необходимость: нельзя обходить
  существующий подходящий лист произвольным названием.

## 7. Формулы, HTML и рисунки

- Сохраняй LaTeX для MathJax: области корней, показатели степеней, дроби,
  индексы, векторы, интервалы и системы. Не упрощай математические выражения.
- Перед А), Б), В) вне формул нужен `<br>`. Разделители строк `\\` внутри
  `cases` и других LaTeX-окружений должны сохраняться.
- Не оставляй непарные `$` незамеченными. Ошибка оформления — явное замечание,
  а не повод молча удалить формулу или объявить полный успех.
- Таблицы условий передавай в поддерживаемый HTML без изменения ячеек. Символ
  модуля `|x|` внутри формулы не должен становиться разделителем колонок.
- Применяй принятый ограниченный набор HTML-тегов для preview. Не вставляй
  распознанный произвольный HTML или скрипты непосредственно в DOM.
- В выдачу входят отдельные рисунки, а не скриншоты всех условий, эмблемы,
  инструкции, водяные знаки или сканы целых страниц.
- Для bitmap учитывай матрицу размещения, поворот страницы и soft mask. При
  необходимости рендери отдельный XObject, без соседнего текста PDF.
- Один xref может использоваться в разных ориентациях: такие размещения нельзя
  ошибочно объединять в один файл. Для обычных размещений сохраняй исходные
  байты, когда преобразование не требуется.
- Привязывай рисунки к реальным задачам и `page_numbers`. Геометрическая B1
  внутри B9 не должна создавать новую колонку и перехватывать рисунки.
- Несколько частей рисунка перечисляй в `image_name` настоящими переводами
  строки в правильном порядке. Число файлов и логических рисунков может различаться.
- Границы векторных рисунков проверяй визуально; эвристическая область требует
  предупреждения. Координаты должны соответствовать видимому повороту страницы.

## 8. Неизменный контракт Excel и ZIP

Листы: ровно `Tasks` и `about`. `Tasks` имеет семь колонок в этом порядке:

```text
task_num, condition, image_name, solution, answer, exams_id, topics_id
```

- Одна строка — одна основная задача со всеми подпунктами.
- `task_num` последователен от 1 внутри варианта; в обработанных старых вариантах
  B1–B14,C1–C6 соответствуют 1–20. Не навязывай 20 задач другим форматам.
- `solution` пустой. Ответы сохраняются текстом, а не преобразуются Excel в числа.
- `image_name` содержит только безопасные имена существующих файлов этого варианта.
- Технические поля, исходные метки и замечания остаются в debug/reports.

`about` имеет строку заголовков и одну строку значений, ровно 11 полей:

```text
class, year, date, topic, exam_id, title, code, source_name, is_public, source_url, description
```

Неизвестные значения пустые. `about.exam_id` относится к экзамену целиком,
`Tasks.exams_id` — к задаче. Не возвращай удалённые технические столбцы.

ZIP строится по явному списку: `tasks.xlsx` и только его рисунки, на одном уровне.
Число записей равно 1 + число файлов рисунков. Проверяй отсутствие дублей,
посторонних файлов, соответствие `image_name`, CRC и побайтовое совпадение с output.
PDF, HTML, JSON, логи, источники и preview в итоговый ZIP не включаются.

Сначала проверяй временную выдачу, затем заменяй конечную с резервной копией и
откатом при ошибке. Сохрани прежний результат при неуспешном новом запуске.
Обычный повтор может пересоздать Excel/ZIP и изменить их SHA-256 из-за упаковки:
это запись данных, а не строго read-only проверка. Для проверки сохранности
старых выдач читай их и сравнивай хеши, не запускай повтор без необходимости.

## 9. DeepSeek, конфигурация и бюджет

Основной провайдер — прямой DeepSeek, один клиент на последовательный пакет.
Не подключай автоматические fallback на Gemini, NVIDIA, Pollinations или Nemotron.

Настройки сверяй с `.env.example` и `DeepSeekSettings`. Исходные значения:

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_CONNECT_TIMEOUT=15
DEEPSEEK_READ_TIMEOUT=120
DEEPSEEK_MAX_TOKENS=16384
DEEPSEEK_CLASSIFICATION_THINKING=disabled
OCR_DPI=300
```

- Существующий `.env` не перезаписывай. Окружение имеет приоритет; загрузчик
  читает значения буквально, без shell-подстановок. Не выполняй `source .env`.
- Не выводи API-ключи, Authorization или полный запрос с base64 в терминал,
  отчёты, тесты и Git. Публикуй только безопасную конфигурацию без секрета.
- OCR всегда использует `thinking: disabled`. Классификация имеет отдельную
  настройку. Изменение thinking влияет на совместимость её кэша.
- Не запускай `check_deepseek.py`, `check_deepseek_ocr.py` и другие модельные
  утилиты как обычные бесплатные тесты: сначала изучи их поведение.
- Успешный холодный вариант с P страницами: P OCR + 1 классификация.
  Полный совместимый повтор: 0 OCR + 0 классификаций. Это норматив успешного
  потока, а не разрешение скрывать дополнительные неуспешные попытки.
- Автоматические AI-повторы, редиректы и предварительные платные пинги запрещены.
  Каждый явный исправительный запуск учитывается отдельно и объясняется.
- Считай фактические попытки непосредственно перед HTTP, включая тайм-ауты,
  ошибки и обрезанные ответы. Скачивания источников учитывай отдельно.
- HTTP 401/402/403 блокируют новые платные обращения пакета. Не переключай
  провайдера или ключ, чтобы обойти ошибку.
- Неполный usage отмечай как неизвестный. Без надёжного тарифа не вычисляй цену
  и не записывай неизвестную стоимость как нулевую.
- `--max-variants` — технический предохранитель, не самостоятельное разрешение
  расширять платный диапазон. При документировании, тестах и обычном рефакторинге
  работай без платных вызовов, если реальная обработка не входит в запрос.
- При изменении API используй актуальную официальную документацию DeepSeek:
  `https://api-docs.deepseek.com/`, руководства Vision, JSON Output и Thinking.

## 10. Совместимость кэшей и возобновление

- После успешной проверки сохраняй каждую страницу независимо. Ошибка следующей
  страницы не отменяет готовые предыдущие страницы.
- Identity OCR включает вариант/URL, SHA-256 PDF, страницу, рендер/DPI,
  провайдера, модель, существенные параметры, промпт/схему и хеши PNG ответов.
- Identity классификации дополнительно учитывает условия/метки, оба CSV,
  допустимые множества категорий и правила классификации.
- Изменение CSV требует новой классификации, а не нового OCR. Изменение одного
  варианта не должно отменять кэши остальных. Переиспользование классификации
  определяется фактическими условиями, а не только хешем PDF.
- При изменении промпта или схемы обновляй версию/identity и соответствующие
  тесты. Не делай старые кэши совместимыми изменением их fingerprint вручную.
- Не удаляй все кэши для устранения локальной ошибки. Сохраняй исходный API-ответ
  и проверяй, какой минимальный этап действительно требует повторения.
- `--resume` использует точные URL и каталоги кэшей манифеста. Новая попытка
  получает отдельный отчёт. Кэш возобновления должен оставаться внутри варианта.
- `--fresh-ai` создаёт отдельный кэш в `fresh/<run_id>` и может вызвать платные
  обращения. Он несовместим с `--resume` в одном запуске.
- `--local-only` запрещает только скачивание источников, а не вызовы модели.
  Для запрета новых AI-запросов явно передавай пустой `DEEPSEEK_API_KEY`.

## 11. Статусы и содержательная сверка

Коды CLI: `0` — SUCCESS/план, `2` — NEEDS_REVIEW, `1` — FAILED,
`130` — прерывание пользователем.

Не считай код 2 отсутствием результата: Excel/ZIP могут быть созданы, но иметь
замечания. Успешный HTTP, валидный JSON, корректный ID и целый ZIP по отдельности
не подтверждают правильность содержания.

- Сверяй формулы, опубликованные ответы, рисунки и смысл тем по источникам.
- Различай текущую выдачу и `previous_result`; не выдавай старый файл за результат
  новой неуспешной попытки.
- `debug/content_review.json` применяется только с совпадающим `fingerprint`.
  Проверка связана с PDF, задачами, метаданными, рисунками и кодом форматирования.
- В fingerprint входят хеши `variant_export.py`, `exporter.py`, `latex_format.py`
  и `task_html.py`: даже правка их комментариев может сделать прежнюю сверку
  несовместимой. Не удаляй это ограничение ради зелёного статуса.
- `approved: true` допустим только после действительно выполненной достаточной
  сверки. При подтверждённых ошибках сохраняй findings и `approved: false`.
- Не редактируй исторические отчёты так, чтобы скрыть неудачные попытки. При
  новой выдаче фиксируй новую попытку и её происхождение.
- При обновлении ссылок сверки после повторной упаковки докажи неизменность
  значений Excel и рисунков; не переноси старое одобрение на новые данные.

## 13. Практические команды

Все команды выполняются из корня проекта. Если `.venv` отсутствует, сначала
изучи `requirements.txt` и порядок установки из README. Не переустанавливай
зависимости без необходимости и не перезаписывай существующий `.env`.

План без AI и без загрузки источников, если каталог уже сохранён:

```bash
.venv/bin/python -u main.py --batch 6-12 --plan --local-only
```

Проверка совместимых кэшей без возможности нового платного обращения
(пересоздаёт выходные файлы, поэтому запускай в рамках задачи обработки):

```bash
DEEPSEEK_API_KEY='' DEEPSEEK_CLASSIFICATION_THINKING=disabled .venv/bin/python -u main.py --batch 6-12 --max-variants 7 --local-only
```

Реальная обработка ниже может стоить денег и допустима в согласованном объёме:

```bash
DEEPSEEK_CLASSIFICATION_THINKING=disabled .venv/bin/python -u main.py --url https://alexlarin.net/ege/2013/trvar6.html --local-only
DEEPSEEK_CLASSIFICATION_THINKING=disabled .venv/bin/python -u main.py --batch 6-12 --max-variants 7 --local-only
```

Возобновление: подставь реальный `RUN_ID`. Для манифеста семи вариантов также
нужно поднять технический лимит с пяти до семи:

```bash
DEEPSEEK_CLASSIFICATION_THINKING=disabled .venv/bin/python -u main.py --resume reports/RUN_ID/manifest.json --max-variants 7 --local-only
```

Не запускай `main.py` без аргументов для проверки CLI: по умолчанию он обрабатывает
542 и при отсутствии совместимого кэша может обратиться к API. Для справки:

```bash
.venv/bin/python main.py --help
```

## 14. Проверки изменений

Выбирай проверки по изменённому поведению. Тесты должны проверять существенные
инварианты, использовать fake/mock для API и временные каталоги для данных.
Не вызывай реальную модель из теста и не записывай fixtures поверх выдач пользователя.
Для чисто текстовых изменений достаточно проверки документа и diff; полный
платный поток не нужен. Не устанавливай новый линтер только ради одной правки.

| Изменение | Основные тесты |
|---|---|
| Источники/метки/год/загрузка | `tests/test_variant_sources.py`, `tests/test_downloader.py` |
| OCR/продолжения/кэши | `tests/test_variant_ocr.py`, `tests/test_provider.py` |
| Категории/деревья/identity | `tests/test_variant_classification.py`, `tests/test_classification.py` |
| Рисунки/Excel/ZIP/публикация | `tests/test_variant_export.py`, `tests/test_exporter.py` |
| LaTeX/подпункты/текст | `tests/test_latex_format.py`, `tests/test_math_text.py`, `tests/test_task_html.py` |
| CLI/бюджет/изоляция/ошибки | `tests/test_main.py`, `tests/test_pipeline.py` |
| Legacy-разбор/542 | `tests/test_recognizer.py`, `tests/test_parser.py`, `tests/test_answers.py` |

Пример релевантной проверки:

```bash
.venv/bin/python -m pytest -q tests/test_variant_export.py tests/test_pipeline.py
```

Полная регрессия для существенных изменений общего потока:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q main.py pipeline.py provider.py pipeline_io.py variant_sources.py variant_ocr.py classification.py variant_export.py exporter.py export_metadata.py latex_format.py math_text.py task_html.py legacy_sources.py
git diff --check
```

В чистом клоне тесты реальных локальных артефактов могут пропускаться: указывай
это честно. Не объявляй старый результат тестов результатом нового запуска.
После успешных релевантных проверок не повторяй их без новых изменений или причин.

Для визуальной проверки открой `preview.html`, вставь семь колонок листа Tasks
и обе строки about. Preview принимает TSV, а не XLSX; рисунки проверяются отдельно
по файлам. Для MathJax нужен интернет. При автоматическом снимке дождись загрузки
математических шрифтов, а не только появления элементов MathJax в DOM.

## 16. Критерии завершения задачи

Перед завершением убедись, что согласованные изменения реализованы, полезное
поведение сохранено, релевантные проверки выполнены, а результат находится

В итоговом сообщении кратко сообщи:

1. Что изменилось и зачем.
2. Где находятся готовые файлы и отчёты.
3. Что фактически проверено; если проверка невозможна — конкретную причину.
4. Какие ошибки или ограничения остаются и что требуется для готовности к импорту.

и не создавай `approved: true` только ради завершения задачи.
